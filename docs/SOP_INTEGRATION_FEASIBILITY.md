# SOP 集成可行性评估报告

> 评估对象：`codex/SOP/`（talent-sop 人才管理五段式 SOP 技能产出）
> 评估基准：OpenGantt 现有架构（见 `docs/PROJECT_KNOWLEDGE.md`）
> 性质：**仅评估，未实施**。结论供决策。

---

## 1. SOP 是什么（事实描述）

- **talent-sop** 是一个 WorkBuddy 技能（`talent-sop.zip` 含 SKILL.md），按五段固定流程为任意岗位产出 7 件套人才管理文档：①胜任力模型表 → ②结构化面试题库与评估表 → ③岗位SOP+培训地图 → ④考核指标一览表+晋升标准 → ⑤九宫格盘点与继任计划。
- 目录内已有两套**示例产出**（商务运营/新媒体运营），全部为**虚构演示数据**；商务运营的胜任力模型标注"v0 初稿（假设版）"，条目来源均为"假设-待验证"——**尚未用真实岗位与真实访谈材料校准**。
- 每段有明确过关条件（如：两主管口径一致、面试分差 ≤1 档、关键岗 30 天有继任方案）。

## 2. 与现有系统的关系（事实对照）

| SOP 五段 | OpenGantt 现状 | 差距 |
|---|---|---|
| ①胜任力模型 / ②面试题库 / ③岗位SOP+培训地图 | **无对应结构**；文档中心可存文件 | 缺"岗位"维度的组织方式 |
| ④考核指标一览表 | **已有**绩效考核模块（模板库/结果存档/评分） | 指标表可作为绩效模板的依据，但**取数自动化**无数据源 |
| ⑤九宫格盘点 | 有绩效结果数据（等级），无"潜力"维度 | 缺双维评分结构 |
| 文档承载 | 文档中心已支持：上传/部门-姓名-日期分组/跨部门授权/树形浏览 | **直接可用，零开发** |

## 3. 三种集成方案（成本递增）

### 方案 A：文档托管归档（成本 ≈0，当天可用）
- 做法：SOP 产出按统一目录规范上传文档中心，如 `SOP/商务运营/01-胜任力模型/`（利用现有"部门-姓名-日期"分组前缀机制，或建"岗位-段位"命名规范）。
- 变更：**零代码**。权限、检索、下载全部复用现有能力。
- 局限：只是文件归档，无结构化联动、无完成状态追踪。

### 方案 B：岗位档案页（轻结构化，约 3–5 天开发）
- 做法：新增"人才 SOP"视图——按**岗位**组织五段档案：
  - 数据结构：新增 1–2 张表（如 `SopPosition`（岗位名/部门/五段状态/过关确认人）+ 引用 Document 外键），**文件本体仍存文档中心**；
  - 页面：岗位列表 → 岗位档案页（五段状态一览/各段文档入口/过关条件勾选/更新记录）；
  - 与 WorkBuddy 联动：talent-sop 技能产出后上传至对应岗位档案（复用现有上传 API）；
  - 与绩效模块衔接：考核指标一览表作为该岗位绩效模板的参考附件（人工对齐，不做自动取数）。
- 接口对接：全部内部（复用 documents 上传/下载与权限），**无外部系统对接**。
- 数据结构变更：新增表 1–2 张（`migrate.py` 自动迁移，零手工 SQL）。

### 方案 C：深度结构化（2–3 周以上，**不建议现在做**）
- 考核指标自动取数（对接业务系统）、九宫格自动生成（绩效×潜力双维）、面试在线评分流程。
- **硬风险**：④段的硬规矩是"月底数据自动出、人工报数降权"——**当前没有任何业务数据源可对接**，强行上线等于把人工报数固化进系统，违反 SOP 自己的原则；"潜力"维度同样无数据来源。

## 4. 潜在风险

1. **示例数据风险（最高）**：现有产出全部为假设/待验证状态——**现在做结构化集成等于把占位值固化**。应先跑通一个真实岗位并完成校准（主管拍板+访谈替换）。
2. **数据源缺失**：方案 C 的核心承诺（考核自动出数）依赖外部业务系统，目前不存在。
3. **双轨维护**：talent-sop 技能持续产出文档 + 系统内结构化模块——若口径不一致会互相矛盾。方案 B 用"文档为唯一本体、档案页只做组织与状态"可规避。
4. **范围蔓延**：人才管理是独立领域，OpenGantt 定位是项目进度管理——过度扩展会稀释核心价值并增加维护负担。

## 5. 结论与建议

**可行性结论：可行，但建议分两步走，当前只做方案 A。**

1. **立即（方案 A，零成本）**：把两套示例 SOP 按统一命名上传文档中心归档，建立"岗位-段位"目录规范——文件本体有归属、有权限、可检索。
2. **触发条件后再做（方案 B）**：当**第一个真实岗位完成五段校准**（有真实访谈与主管拍板）且团队确认要常态化运行时，投入 3–5 天做岗位档案页（轻结构化）。
3. **暂缓（方案 C）**：自动取数与九宫格自动化等数据源问题解决前不启动。

**决策点**：是否先执行方案 A（上传归档）；是否把方案 B 列入待办。
